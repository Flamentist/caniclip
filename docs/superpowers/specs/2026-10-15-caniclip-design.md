# CaniClip — Design Spec

Date: 2026-10-15
Status: Draft for review

## 1. Purpose

CaniClip is a menu bar macOS app for capturing the screen, annotating screenshots, and recording a screen area to an animated GIF. It is a deliberately smaller CleanShot: no cloud upload, no scrolling capture, no OCR, no video formats other than GIF in v1.

Success looks like this:

- Press a global hotkey from any app, drag a region, and have a screenshot in the editor within a second.
- Annotate with a handful of tools, then copy or save with one click.
- Press a hotkey, drag a region, record, press stop, and get a small, good-looking GIF on disk and in the clipboard.
- Change every hotkey in Settings.

## 2. Stack and language split

| Concern | Owner | Why |
|---|---|---|
| Menu bar item, windows, selection overlay, editor, settings | Swift (SwiftUI + AppKit) | Native look and feel; first-party APIs |
| Global hotkeys and hotkey recorder UI | Swift, `KeyboardShortcuts` package | Mature, includes a recorder view, handles conflicts |
| Screen capture and area recording | Swift, ScreenCaptureKit | First-party; avoids binding friction |
| GIF encoding, pixelation, image math | Rust crate `caniclip-core` | `gifski` is the best GIF encoder available; Rust is the right home for pixel work |
| Swift ↔ Rust bridge | UniFFI 0.32 (proc-macro mode) | Type-safe generated Swift; no hand-written C |
| Xcode project | Generated by XcodeGen from `project.yml` | Reproducible and reviewable |

Targets: macOS 15 and later, Apple Silicon only in v1 (an x86_64 slice can be added to the Rust build script later).

Toolchain on this machine: Xcode 26.3, Swift 6.2, XcodeGen and Homebrew installed. Rust is installed with rustup as part of setup.

Rust builds as a static library linked directly into the app target. There is no intermediate Swift package: XcodeGen sets `SWIFT_INCLUDE_PATHS`, `LIBRARY_SEARCH_PATHS` and `OTHER_LDFLAGS` to pick up the header, modulemap and `libcaniclip_core.a`. A pre-build run-script phase calls `scripts/build-rust.sh`, which runs `cargo build --release` and then `uniffi-bindgen generate --library` into `CaniClip/Generated/`.

## 4. Rust core API

Exposed with UniFFI proc-macros. Pixel buffers cross the boundary as `Vec<u8>`; one copy per frame is acceptable at 15 fps for region-sized frames.

```rust
#[derive(uniffi::Enum)]
pub enum PixelFormat { Rgba, Bgra }

#[derive(uniffi::Record)]
pub struct GifSettings {
    pub max_width: Option<u32>,   // frames are downscaled to fit, aspect preserved
    pub max_height: Option<u32>,
    pub quality: u8,              // 1..=100, gifski quality
    pub fast: bool,               // gifski fast mode
    pub repeat: i32,              // -1 = play once, 0 = loop forever, n = loop n times
}

#[derive(uniffi::Object)]
pub struct GifEncoder { /* Mutex<Option<Collector>>, writer JoinHandle, temp path */ }

#[uniffi::export]
impl GifEncoder {
    #[uniffi::constructor]
    pub fn new(settings: GifSettings) -> Result<Arc<Self>, CoreError>;
    pub fn add_frame(&self, pixels: Vec<u8>, width: u32, height: u32,
                     format: PixelFormat, timestamp_secs: f64) -> Result<(), CoreError>;
    pub fn finish(&self, output_path: String) -> Result<GifSummary, CoreError>;
    pub fn cancel(&self);
}

#[derive(uniffi::Record)]
pub struct GifSummary { pub frame_count: u32, pub file_size_bytes: u64, pub duration_secs: f64 }

#[uniffi::export]
pub fn pixelate(pixels: Vec<u8>, width: u32, height: u32,
                x: u32, y: u32, w: u32, h: u32, block_size: u32) -> Result<Vec<u8>, CoreError>;

#[uniffi::export]
pub fn core_version() -> String;

#[derive(uniffi::Error, thiserror::Error)]
pub enum CoreError { InvalidInput(String), Encoding(String), Io(String), AlreadyFinished }
```

Encoder internals: `gifski::new(settings)` returns a `Collector` and a `Writer`. The writer must consume while the collector produces, so the constructor spawns a writer thread that streams into a temp file in the system temp directory. `add_frame` converts BGRA to RGBA if needed, wraps the buffer as an `ImgVec<RGBA8>`, and calls `add_frame_rgba`. `finish` drops the collector, joins the writer thread, moves the temp file to the output path, and returns the summary. After `finish` or `cancel`, further calls return `AlreadyFinished`. Frames whose dimensions differ from the first frame are rejected with `InvalidInput`.

Pixelate averages each `block_size` square inside the rect and fills it with that average. Rect is clamped to the image. Used by the editor's pixelate tool at export and preview time.

## 5. Swift app

### 5.1 App shell

- `LSUIElement = true`: no Dock icon, no main menu. The app lives in the menu bar.
- `StatusItemController` owns the `NSStatusItem`. Menu: Capture Area, Capture Full Screen, Record Area to GIF, separator, Settings…, Quit. The icon swaps to a red dot while recording; clicking it then stops the recording.
- `AppState` is a single `@MainActor` observable object holding `Preferences`, the current mode (idle, selecting, editing, recording) and references to open windows. Mode transitions are the only way UI flows start, which keeps hotkeys, menu items and the overlay consistent.

### 5.2 Hotkeys

`KeyboardShortcuts.Name` values: `captureArea`, `captureFullScreen`, `recordArea`. Defaults are ⌘⇧7, ⌘⇧9 and ⌘⇧8, chosen to avoid the system's ⌘⇧3/4/5. Handlers call into `AppState`. While a recording is active, the record hotkey stops it. Settings shows a `KeyboardShortcuts.Recorder` per action.

### 5.3 Permissions

Screen Recording permission is checked with `CGPreflightScreenCaptureAccess()` at launch and before each capture. If missing, the app calls `CGRequestScreenCaptureAccess()` and shows a sheet explaining that macOS requires a relaunch after granting, with a button that opens the Privacy & Security pane. The app is signed with the development team so the permission grant persists across rebuilds.

### 5.4 Selection overlay

One borderless `NSWindow` per `NSScreen`, level `.screenSaver`, `ignoresMouseEvents = false`, transparent background, covering the full screen frame. Behaviour:

- Dims the screen by 35 percent; the dragged rectangle is undimmed with a 1 pt white border and a size label (`W × H`) in device pixels.
- Crosshair cursor. Drag to select. Shift constrains to square. Esc cancels. Space while dragging moves the selection.
- Screenshot mode: capture happens on mouse up.
- Record mode: on mouse up the overlay freezes the rectangle, shows a small start toolbar beneath it (Start, Cancel, fps and cursor toggles mirroring Settings), and waits. Start hands the region to `RecordingController`.
- All overlay windows are excluded from capture via the ScreenCaptureKit content filter so they never appear in the output.

### 5.5 Capture

`ScreenCapturer` uses `SCShareableContent` to find the display under the cursor and `SCScreenshotManager.captureImage(contentFilter:configuration:)` to grab a `CGImage` at native pixel scale. Area capture sets `sourceRect` in points and output size in pixels. Full screen capture uses the display under the cursor. Results open the editor or follow the configured after-capture action (open editor, copy to clipboard, save silently).

### 5.6 Editor

`EditorWindow` is an `NSWindow` hosting a SwiftUI view. The chrome (toolbar, color picker, stroke width, undo/redo, Copy, Save, Save As…) is SwiftUI. The drawing surface is `AnnotationCanvasView`, an `NSView` wrapped in `NSViewRepresentable`, because precise mouse handling and hit testing are simpler in AppKit.

Model:

```swift
enum Annotation: Identifiable, Codable {
    case arrow(id, from, to, style)
    case rect(id, frame, style)
    case ellipse(id, frame, style)
    case pen(id, points: [CGPoint], style)
    case highlighter(id, points: [CGPoint], style)   // wide, 40 % alpha, multiply blend
    case text(id, origin, string, style)
    case pixelate(id, frame, blockSize)
}
struct Style { var color: Color; var strokeWidth: CGFloat; var fontSize: CGFloat }
```

All geometry is stored in image pixel coordinates; the view applies a single scale transform, so Retina screenshots and export share one code path. `AnnotationRenderer.draw(_ annotations:, image:, into: CGContext)` is used for both on-screen drawing and export rasterization. Pixelate calls the Rust `pixelate` function on the source image region and caches the result per annotation until its frame changes.

Tools: Select/Move, Arrow, Rectangle, Ellipse, Pen, Highlighter, Text, Pixelate. Select allows dragging an existing annotation and Delete removes it. Undo/redo is a stack of model snapshots via `UndoManager`. No crop, no layers, no shape fill in v1.

Export: Copy puts a PNG and a TIFF representation on `NSPasteboard`. Save writes PNG to the configured folder using the naming pattern `CaniClip YYYY-MM-DD at HH.mm.ss.png`. Save As… uses `NSSavePanel`. Closing with unsaved annotations asks to save, discard or cancel.

### 5.7 Recording

`RecordingController` owns one recording at a time.

1. Builds `SCContentFilter(display:excludingWindows:)` excluding CaniClip's own windows.
2. Configures `SCStreamConfiguration`: `sourceRect` = region in points, `width`/`height` = region in pixels, `pixelFormat = kCVPixelFormatType_32BGRA`, `minimumFrameInterval = 1/fps`, `showsCursor` from Settings, `queueDepth = 5`.
3. Creates a Rust `GifEncoder` with settings from Preferences (quality, max width, fast mode).
4. Implements `SCStreamOutput`. Each `CMSampleBuffer` is locked, its BGRA bytes copied once into a `[UInt8]` (handling row stride), and passed to `encoder.addFrame(...)` on a serial background queue with the sample's presentation timestamp relative to the first frame. If the queue depth exceeds 10 pending frames, frames are dropped and a counter is incremented so timing stays correct.
5. Shows `RecordingHUD`, a small floating panel near the region with an elapsed timer and a Stop button. Stop is also triggered by the record hotkey, the menu bar icon, or reaching the configured maximum duration.
6. On stop: stops the stream, waits for the queue to drain, calls `finish(outputPath)`, writes the GIF to the configured folder with the same naming pattern and `.gif` extension, copies the file URL to the clipboard, and shows a quick-access popover anchored to the menu bar item with a thumbnail, file size, Copy and Reveal in Finder.

Defaults: 15 fps, quality 90, max width 1200 px, loop forever, cursor shown, max duration 60 s.

### 5.8 Settings

SwiftUI `Settings` scene with three tabs:

- General: save folder picker, after-screenshot action (open editor, copy, save), launch at login (`SMAppService`).
- Shortcuts: three `KeyboardShortcuts.Recorder` rows.
- Recording: fps (10, 15, 20, 30), quality slider, max width (800, 1200, 1600, original), show cursor, max duration.

`Preferences` is a `Codable` struct persisted in `UserDefaults` under one key; `KeyboardShortcuts` persists its own values.

## 6. Data flow

Hotkey or menu → `AppState.begin(mode)` → `SelectionOverlayController` → region → either `ScreenCapturer` → `CGImage` → `EditorWindow` → export, or `RecordingController` → `SCStream` frames → Rust `GifEncoder` → file → quick-access popover.

The Rust core never touches the UI, files chosen by the user, or preferences. It receives bytes and a path and returns bytes or a summary.

## 7. Error handling

- Permission missing: handled before any capture with the explanatory sheet. Never crash on `SCShareableContent` errors; surface a notification.
- Capture failure: `NSAlert` with the underlying error description; return to idle.
- Encoder failure mid-recording: stop the stream, show an alert, delete the temp file.
- Disk full or unwritable folder: alert and offer Save As….
- All Rust errors are typed `CoreError` values mapped to Swift errors with messages; no panics across the FFI boundary (`panic = "abort"` is off; functions catch and convert).

## 8. Testing

- Rust: unit tests for BGRA→RGBA conversion, dimension mismatch rejection, `AlreadyFinished`, pixelate on known inputs, and an integration test that encodes ten synthetic frames and asserts a valid GIF header, frame count and non-trivial size.
- Swift XCTest: `Annotation` geometry (hit testing, moving), `AnnotationRenderer` produces identical output for scaled and unscaled contexts (pixel diff on a small synthetic image), file naming, Preferences round trip.
- Manual smoke checklist in `docs/superpowers/specs/smoke-test.md`, run before each milestone: grant permission, each hotkey, each tool, copy and save, record 5 s and open the GIF in Preview, change a hotkey and confirm it works.

## 9. Milestones

1. Scaffold: Rust installed, cargo crate with `core_version`, XcodeGen project linking it, app launches to a menu bar icon. Verifies the full bridge.
2. Capture: hotkeys, overlay, full screen and area screenshot, copy and save.
3. Editor: all tools, undo, export.
4. Recording: SCStream to Rust encoder, HUD, quick-access popover.
5. Settings and polish: preferences, launch at login, permission sheet, smoke test pass.

## 10. Out of scope for v1

Cloud upload, scrolling capture, window capture mode, OCR, MP4 or WebP export, crop in editor, multi-monitor spanning selections, Intel builds, App Store sandboxing, auto-update.
